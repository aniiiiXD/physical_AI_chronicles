01
Foundation

A thread is just saved state

Strip away the OS abstraction. A thread is three things: a program counter, a stack pointer, and a register file. When the scheduler pauses you, it saves those to RAM. When it resumes you, it loads them back. That's a context switch.

ARM64 Register File — your Mac's thread context

Click any register to "activate" it. On context switch, all 31 are serialised to RAM.

📐

Full ARM64 thread context: 31×64-bit GPRs + 32×128-bit SIMD/FP + PC + PSTATE = ≈ 4 KB. A context switch physically copies those 4 KB to a kernel data structure in RAM.

Context Switch — what the kernel does

OS timer fires (every ~1 ms). Kernel saves Thread A's register file to its task_struct in RAM. Loads Thread B's register file. CPU resumes Thread B as if nothing happened.

⚠

CPU context switches cost 2,000–10,000+ cycles — register save/restore, TLB flush, cache cold-start. GPU warp switches cost exactly 0 cycles. That's the fundamental difference.

What a "bit" physically is

🔁
Register
D flip-flop. Two cross-coupled NAND gates. Holds state as long as power flows. 1-cycle access.
🔷
SRAM (Cache)
6 transistors per bit. No refresh needed. Fast but expensive — only used for caches.
⚡
DRAM
1 capacitor + 1 transistor. Charge leaks — needs refresh every 64 ms. Cheap and dense.

Cache line = 64 bytes = 512 bits

Memory never moves one byte at a time. Every access loads a full 64-byte line. Access arr[0] and you get arr[0..15] for free.

← 64 bytes. Green = requested. Blue = loaded for free.

Virtual → Physical (TLB)

Your pointer is a virtual address. The MMU translates it to physical RAM via page tables. The TLB caches recent translations — a TLB miss adds 100+ cycles on top of whatever memory latency you were already paying.

// pointer in your code (virtual):
int* p → 0x7ffe3a80
// TLB translates to physical:
0x7ffe3a80 → 0x3c0a1a80

GPU Memory Hierarchy

The GPU hides latency not through prediction or caching tricks, but through sheer numbers. When one warp stalls on a memory load, the scheduler instantly picks another. No registers are saved. No cycles wasted. The register file is always there.

Unlike a CPU which saves/restores registers on context switch, a GPU SM keeps ALL active warp registers in its 256 KB register file simultaneously and permanently. Warp switching is free because no data moves — the scheduler just picks a different slice of the register file.

Use CPU when

  • Complex branching logic
  • Low-latency single requests
  • Serial dependencies
  • OS / I/O / syscalls
  • Small data (fits in L1)
  • Tokenizer, scheduler, TTS post-proc

Use GPU when

  • Same op on millions of values
  • Matrix multiply (attention, conv)
  • No cross-thread dependency
  • High arithmetic intensity
  • Need > 500 GB/s bandwidth
  • Training & batch inference

On-device AI split

  • CPU · tokenize, sample, decode
  • GPU · attention GEMM layers
  • CPU · voice / TTS post-proc
  • GPU · embeddings, FFN, conv
  • Unified mem · Apple shares DRAM
